# 视觉输出规范

视觉的目的，是让复杂关系更容易看懂并让年轻用户愿意继续读，不是用装饰掩盖信息不足。

## 默认视觉语言

- 用 `☉ ☽ ↑ ☿ ♀ ♂ ♃ ♄ ♅ ♆ ♇` 等符号做导航，但首次出现仍写中文名。
- 用短标题、留白、卡片、关键词胶囊和少量 emoji 建立节奏；一屏只突出一个重点。
- 色彩语义保持稳定：主线用金色意象，情绪用蓝紫，行动用红橙，成长用青绿；纯文字环境用符号代替颜色。
- 不连续堆叠十个以上 emoji，不使用闪烁字符或低可读性的花体字。
- 手机端默认不用宽表格；需要对照时改成上下排列的卡片。

## 四种必备图形

### 行星或结构卡

每张卡有标题、关键词、盘面依据、顺畅模式、压力模式、生活镜头和行动。卡片不是百科词条，至少包含一个现实触发场景。

### 相对强度条

用 `████░` 或 1–5 个圆点表示本报告内部的相对强调，并紧跟说明：

“强度仅表示本盘内的相对象征强调，来自配置数量、紧密度与整合重要性，不是科学评分、概率或好坏分数。”

没有可复核规则时不要给精确百分比。

### 关系雷达

适用于亲密关系、人际或合盘。维度可包括：靠近速度、情绪表达、自由需求、稳定需求、冲突强度、修复意愿。纯文本用 1–5 格条形图并解释每一维来自哪些盘面要素，不能只展示图。

### 内在张力图

格式示例：

`需要 A → 触发情境 → 自动反应 → 现实代价`

`保护资源 B ───────────────↗`

至少画出一条拉扯轴和一条调节路径。每个节点都必须由盘面依据支持。

## 输出形态

### 对话视觉版

默认形态。使用 Markdown 标题、引用卡、符号条、简易关系图和短段落。优先保证手机阅读，不依赖表格对齐。

### 移动端网页

用户选择网页时，生成真正可打开的单页报告。视觉风格年轻、沉浸但不过度玄幻，包含：封面、目录、卡片、折叠详情、强度条、关系雷达或张力图。可加入轻微的浮动、渐入、星点或卡片翻转动画；动画不得妨碍阅读，并支持 `prefers-reduced-motion`。默认移动端优先，正文可复制，关键结论不能只存在于动画中。

### 长图或海报

用户选择图片时，优先生成一张摘要长图或三至五张章节卡片，并在对话中同时提供可复制的核心文字。视觉稿不得伪造星盘数据；生成图上的中文必须检查可读性，信息过多时宁可拆图。

### 文档或 PDF

用户选择文档时，生成带封面、目录、章节卡、页眉页脚和图形摘要的可下载报告。保持文字可选择、可搜索；图形下方写明数据含义与限制。

若当前环境无法生成用户选择的文件形态，先交付完整的对话视觉版，再清楚说明未生成的形态；不能只给设计建议代替报告。

## 年轻化阅读节奏

1. 前 150 字出现有区分度的主线或矛盾，不用长免责声明开场。
2. 每 300–500 字安排一次视觉停顿：卡片、强度条、场景镜头或一句自检。
3. 章节标题像内容预告，例如“你不是慢热，你是在确认失控成本”，但正文必须有盘面依据。
4. 神秘感来自结构被逐层揭示，不来自绝对预言、恐吓或含糊套话。
5. 结尾给一条清晰行动路线和可继续探索的方向，让报告有完成感。
